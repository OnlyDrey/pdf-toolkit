## VersionFix and real conversion assessment

Header-only rewriting now accepts every supported higher/lower target (1.0–1.7, 2.0), validates the PDF and preserves its length and all bytes outside offsets 5–7. Catalog `/Version` overrides are preserved and surfaced, never silently rewritten. Editing may invalidate signatures; unsupported features remain. Concise bilingual lower-version/catalog warnings and optional detail text make no reader-compatibility or PDF/A claims. Unit tests cover both directions, exact preservation, catalog overrides, invalid/encrypted input and unsupported targets; browser tests cover lower/higher output and Norwegian text.

True conversion is deferred. The installed MIT-licensed pdf-lib provides structural edits/serialization, not a feature-audited arbitrary version downgrade. Disabling object streams alone cannot convert transparency, color management, forms or signatures. MuPDF's browser/WASM engine is a real candidate, but npm metadata for 1.28.1 reports AGPL-3.0-or-later and 14,324,000 unpacked bytes; integrating it would require licensing review, a substantial maintained binary, worker/isolation/security review and feature-specific output validation. Its write/clean options do not establish arbitrary older-reader compatibility. Ghostscript/pdfwrite-style compatibility conversion similarly needs a reviewed WASM distribution/license and can transform forms, transparency and signatures; rasterization/flattening would violate this task. No conversion engine or upload API is added. Validate representative files/features and licensing before any future opt-in converter.

References: [pdf-lib API](https://pdf-lib.js.org/docs/api/classes/pdfdocument), [MuPDF JS](https://github.com/ArtifexSoftware/mupdf.js), [Ghostscript PDF creation](https://ghostscript.readthedocs.io/en/latest/VectorDevices.html). Package size is unpacked metadata, not a promised browser transfer size.

## Canonical branding

`app/public/brand-mark.svg` contains the exact five path geometries from the existing Lucide FileText icon (lucide-react 1.66.0), preserving stroke width, round caps/joins and the original 20px glyph within the 36px navbar tile. Navbar masking inherits the existing light/dark foreground tokens. `app/scripts/generate-icons.mjs` derives the themed favicon SVG and fixed-background 16px/32px PNG and 180px Apple Touch Icon using the already installed Playwright/Chromium toolchain. No PWA/manifest or image-generation dependency is introduced. The canonical SVG and derived favicon retain the Lucide ISC notice; do not substitute a new PDF symbol.

Regenerate with `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chromium node app/scripts/generate-icons.mjs` (omit the environment override when Playwright Chromium is installed). PNG rendering may differ across browser versions; canonical vector geometry is authoritative. Browser tests verify actual SVG/PNG MIME, signatures/dimensions and navbar asset use, including when pointed at production Nginx. The old favicon href had no corresponding public asset.

## Shared interaction and UI remediation

All form IDs are tool-prefixed. Document language follows the selected translation. Navigation remains semantic Radix tabs with horizontal arrow-key selection and a predictable Tab move into the active panel; labels wrap/reflow at narrow widths. Selection uses only a bottom border, hover uses a subtle background and keyboard focus uses a distinct inset outline. A skip link bypasses the header/navigation. Shared focus-visible rules use existing ring tokens, remain visible in both themes and honor forced colors; reduced-motion media rules shorten nonessential animation.

Destructive text has a separate contrast-safe token in each theme, while filled destructive buttons retain readable foregrounds. Discard uses a restrained destructive ghost variant and a native modal confirmation with Cancel initially focused, Escape restoration and selected-tool focus after confirmation. Save/download also restores focus after the toolbar disappears. Reorder/remove controls have 32px targets; checkboxes have 24px targets and labels. Input/drop-zone boundaries are strengthened without changing decorative card borders.

All tools expose persistent processing announcements, busy regions, named previews and error descriptions. Invalid file types receive explicit feedback; drop targets show drag feedback and are disabled during processing. Unselected thumbnail text no longer loses contrast through whole-button opacity. Unique labels, heading hierarchy, narrow-screen card padding, preview sizing and long filenames are addressed without changing PDF operations. Native PDF preview canvases remain visual summaries, not screen-reader representations of document contents.

Targeted validation: types, lint, 45 unit tests and six desktop/mobile keyboard/language/VersionFix interaction cases pass. Automated axe coverage and manual visual review follow separately; this is not a WCAG certification.

## Automated accessibility coverage and follow-up fixes

The Playwright axe integration checks all seven tools with a real working PDF in English/Norwegian and light/dark themes on desktop/mobile (56 tool/theme/language combinations), plus processing, invalid PDF/margins, menus and confirmation states. It enables WCAG 2 A/AA, 2.1 A/AA, 2.2 AA and axe best-practice rules without disabling individual rules. Modal scans cover the active listbox/dialog; separate assertions verify native background isolation and keyboard focus/restoration instead of requiring an inaccessible background heading inside a modal.

These checks exposed additional issues: light muted toolbar text measured 4.29:1 on its tinted surface (1.4.3), language/drop-zone accessible names omitted visible content (2.5.3), and enlarged text overflowed toolbar/button rows (1.4.4/1.4.10). Muted text is darker, names derive from visible content plus expanded language names, actions wrap, filenames break safely and Crop margins stack on narrow screens. Out-of-range Crop overlays are clipped to the noninteractive preview instead of intercepting controls. Merge keyboard instructions and reorder announcements are localized; its inline upload is disabled during processing. Modal selects complement Radix focus handling with native inert background controls; Discard cycles focus between its controls and Escape remains available.

Keyboard tests cover tab navigation, file selection, merge reordering, invalid drops, confirmation cancellation/acceptance and focus restoration. Reflow tests use 320/640 CSS-pixel viewports and a 200% root text-size test; these are layout checks, not a claim of manual browser-chrome 400% zoom testing. Reduced-motion behavior is asserted. Automated checks cannot establish full WCAG compliance: real screen-reader testing, browser/OS high-contrast settings and manual 200%/400% browser zoom still need representative Windows/macOS/mobile review.

Production-container testing caught a deployment-only branding defect: public files created under a private host umask were copied as root-owned `0600` assets, so UID 101 received 403 responses. The Docker builder now normalizes generated static directories to `0755` and files to `0644`, retaining root ownership and the non-root/read-only runtime. Container checks explicitly fetch all five branding/favicon assets; browser checks verify SVG/PNG MIME, signatures and dimensions. Vite-only checks would not have established this deployment behavior.
